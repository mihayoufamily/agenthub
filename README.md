# AgentHub

多 Agent 工作台与工作流协作桌面应用（Windows 优先）。

![welcome](docs/screenshots/01-welcome.png)

## 下载即用（免安装）

从 [Releases](https://github.com/mihayoufamily/agenthub/releases/latest) 下载 zip → 解压到任意目录 → 双击 `AgentHub.exe`。

- 本地数据保存在 `%APPDATA%\agenthub\`，删除该目录即可彻底清除
- 首次使用建议：添加 Agent → 演示 Agent，无需任何配置即可体验完整流程
- 应用内会自动检查新版本（GitHub Releases，3 天一次），发现新版顶部提示，前往 Releases 手动下载

## 这是什么

AgentHub 提供两种工作方式：

- **工作台模式**：在同一个应用里自由切换多个 Agent，每个 Agent 保留自己的会话、输入草稿与运行状态；支持拖拽排序、Shift+滚轮切换、Agent 间交接、每 Agent 多会话（新建/切换/重命名/删除，草稿随会话保留）。
- **工作流模式**：规划 Agent → 执行 Agent → 审核 Agent 依次协作，未通过审核则返工（默认最多 3 轮，可配置），支持自动审核与人工确认两种方式，完成后输出交付卡片。

视觉与交互对标 Codex / WorkBuddy / DSH / 豆包 / Tabbit 的产品形态（仅界面与交互，不涉及模型能力，不使用任何第三方品牌素材）。

## 快速开始（源码运行）

```bash
npm install          # 国内网络可用：npm install --registry=https://registry.npmmirror.com
npm run dev          # 构建并启动桌面应用
```

要求：Node.js ≥ 18，Windows 10/11（已在 Windows 上实际验证）。

## 打包

```bash
npm run pack:portable   # 生成免安装便携目录 release/AgentHub-win-x64/（本机已验证；明文 resources/app，不打 asar）
npm run dist            # 生成 NSIS 安装包（asar: true）。需要管理员终端；非管理员会在 app-builder 那步报 Access denied / ERR_ELECTRON_BUILDER_CANNOT_EXECUTE（见下述已知限制）。CI 侧由 Release 工作流的 installer 任务（手动触发）产出
```

- 工作流真实引擎：三角色为自定义模型 Agent 时经 OpenAI 兼容接口**真实流式调用**（角色提示词注入、结构化验收清单输出、解析失败降级纯文本并转人工确认）；审核无法逐项判定时不放行也不盲目返工；演示 Agent 参与的角色逐卡标注"演示"，绝不把脚本内容包装成真实执行

- 工作流预设：把当前三角色（含各角色的模型覆盖）存成一个命名预设，一键套用。**预设只动"用谁来干"**——目标文字、产物目录、审核方式与轮次不受影响；同名保存即更新。旧的"保存任务（目标 + 配置的快捷卡片）"已删除
- 工作流任务列表（不限个数）：左侧栏「工作流」区列出所有任务（进行中/待确认排前，其余为可回看的历史），点开设定目标与产物即切换过去继续看；新建按钮开新任务，逐条可删（连同落盘记录）。**数据源就是任务记录本身**，所以进度天然随退出保留、不需要第二套存储；重启后正在跑的部分标为「状态未知」并等用户手动继续，绝不自动重放（2026-10-25 起：所有崩溃残留的 running 记录一次性核销落盘，不只最新那条——多次崩溃积累的旧记录点开不再空占引擎位）；中断续跑按"最后一张**真产出过结论**的角色卡"推断（status done 且结论非空，崩溃在半路的角色重跑而不是跳过）
- 单执行循环约束：同一时刻只有一个工作流在跑，正在执行时切换/新建/删除会被拦住并说明原因（不会出现两个任务抢同一个引擎、半途互相覆盖状态的假并行）。2026-10-25 审查轮把这层防护从"半成品"补成闭环：占用位 `_started` 在 start() 校验后**同步**置位（原先排在两个 IPC 之后，双击"开始"能起两条并发链）；续跑/单角色重跑/批准后续跑共用同一把占用位且入口先查；带门起链（重跑/交付/返工/批准）先清门再置 running（原先"门还挂着但已在跑"会让切换守卫失效）；引擎所有写入按 **runId 归属**（迟到的事件写不进切换后的别的任务，此前可写穿并落盘）；单角色重跑收尾把状态与门还原到重跑前快照（原先永停 running 空占引擎位）；确认交付的流式期间点「停止」被尊重（原先被收尾覆盖成 completed）；链上任一未捕获异常统一兜底为 failed + notes 留因（原先卡死 running 无提示）；超时看门狗覆盖全部续跑链（原先只有 start 有）
- 两种模式共用同一根左侧栏（Agent 列表 / 工作流列表 / 切换模式 / 设置固定同一处）：工作流页面不再有自己的右上角入口，切模式时界面骨架不动
- 后台运行可见性：任务在跑时离开工作流界面（回工作站聊天）不会中断；侧栏常驻一行进度（当前轮次与状态），到确认门或结束时发系统通知（窗口正聚焦则不打扰，避免重复）
- Agent 常驻提示词：每个 Agent 可写一段"我对这个执行者的长期要求"，工作站每次对话与工作流每个角色调用时自动拼上；工作流里排在角色协议**之后**，不会覆盖输出格式与能力边界
- Skill 体系：启用/禁用开关（禁用后不出现在引用列表也不注入）、**兼容 Agent Skills 开放标准**（导入含 `SKILL.md` 的目录，读 frontmatter 的 name/description，登记 `references/`、`scripts/` 等附带文件路径）、渐进式加载（引用的给正文，未引用的只给一行清单）。**不执行 skill 里的脚本**，要跑仍走命令授权
- 图片附件：png/jpg/jpeg/webp/gif（单张 ≤4MB），模型侧走 OpenAI 兼容的多模态 `image_url` + data URL，输入框显示缩略图；CLI 侧没有统一多模态入参，只把本机路径写进提示词并注明"由该 CLI 自行读取"。已知不支持视觉的模型直接拦下，未登记的提示后放行（不替服务端下结论）
- 调用账本与用量统计：每次真实调用落一条**只含元数据**的账本（耗时、事件数、token、错误信息；不记正文与凭据）。设置 → 用量统计按 harness × 模型聚合调用数/失败数/token/费用/均耗时，未上报 usage 的调用如实标注次数而不估算；对话栏底部一个图标按钮可直接看本 Agent 的统计与最近调用，支持导出 JSONL 与清空
- 快捷键自定义：切模式 / 打开设置 / 停止工作流 / 新建工作流四项可在设置里改键（按下即录制、冲突拒绝、可回默认）；**必须带修饰键**，不给裸键设全局键以免吃掉正常输入
- 角色级模型覆盖真实生效且持久：在工作流的角色浮层里换模型会写入配置，重启与"开始任务"都不再被抹回 Agent 自带模型（此前 `resolveRoles()` 重建角色对象时丢掉 `modelOverride`，表现为"工作流里切了模型又变回原模型，必须先去工作站切"）
- 交付卡片：完成内容、验收对照、产物列表（每个产物可点开本机文件）、产物目录（可一键打开文件夹）、导出任务记录（真实写盘）、继续修改（沿用上一任务执行/审核上下文）、新建任务
- 模式切换：运行中任务弹红色警告（图标 + 文字 + 默认焦点在安全项）；`Ctrl + M`（默认，可改键）在工作站 ↔ 工作流之间互切（设置弹窗打开时、非这两个界面时不响应；运行中同样先弹确认）
- 关闭应用要过确认（Electron 37.10.3）：**不再使用 Electron 默认应用菜单**——它的 Window ▸ Close（Ctrl+W）会直接关掉唯一窗口 → `window-all-closed` → 应用静默退出，`autoHideMenuBar` 只藏栏不注销加速键；同一条路径上的 **Ctrl+R 强制刷新**更阴，会把正在跑的工作流当场打断（渲染进程重载）。现在：没在跑 → 关闭即退出；正在跑 → 弹系统确认框，默认高亮「后台继续运行（收到托盘）」，另两选「仍然退出应用」「取消」；Alt+F4 与任务栏关闭走同一条判断。托盘常驻"显示主窗口 / 退出 AgentHub"，缩到托盘后再次双击应用图标会把窗口叫回来（不是"看起来没反应"）；通知点击也会唤回窗口
- 项目约定自动读取：进入工作目录自动读 `AGENTS.md` / `CLAUDE.md` 原文注入（工作站按 CLI 的 workDir 或模型 Agent 的沙箱根，工作流三个角色按产物目录），不用再手抄进 Agent 常驻提示词。注入顺序固定为**角色协议 → 项目约定 → 历史记忆 → 角色技能 → 常驻要求**，协议（输出格式与能力边界）不会被仓库里的文字覆盖；文件名与截断都在段落里如实标出
- 命令白名单 + 审批历史：`allowCommands` 不再是一刀切。默认逐条确认，三层判定：① 危险形态（`rm -rf`（含 `--recursive --force` 长选项）、`del /s`（含 `del/s` 无空格写法）、`rd|rmdir /s`、`format`、`curl|sh` 与 PowerShell 一族（`iwr|iex`、`Invoke-Expression`、`powershell -enc`）、`git push --force`（含 `-f` 短旗标）、`git reset --hard`、`git clean -f`（含 `-fd` 任意位）、`reg add|delete`（含 `reg.exe`）、`Remove-Item -Recurse` 等）**白名单覆盖不了**，永远要确认——清单是启发式不是完备集（2026-10-25 审查轮补齐短旗标/无空格/`.exe` 后缀/长选项/PS 一族变体，断言钉在 fixes-check）；② 命令按 **cmd 真实语义**拆段逐段核对：`&&` `||` `;` `|` **单 `&`** 与**换行**都是段边界，引号区只认双引号（`'` 在 cmd 里不是引号）、`^` 转义下一字符——`npm test && del x`、`git status & powershell …`、`npm test ' & del x` 都不能因为前一段在白名单里就整条放行（拆段器原先不认单 `&` 且把 `'` 当引号，与 cmd 语义相反，前缀白名单可被搭载第二命令，2026-10-25 已修并有端到端断言）；③ 规则默认整段相等才放行，以 `*` 结尾才是前缀放行。已知残留：`%VAR%` 展开出分隔符发生在解析前后，本层看不到变量内容，只能靠"未覆盖段要确认"兜底。裁决与历史落 `userData/approvals.json`（原子写），超时/取消/界面没接住一律按拒绝；弹窗默认焦点在「拒绝」。要无人值守可在 Agent 工具面板显式改回「授权即放行」；审批历史在设置页的回显走 `redactCommandForDisplay` 脱敏（与工具卡同一口径，2026-10-25 起）
- 改动检查点与回滚：工具层每次改文件前 copy-on-write 备份原件到 `userData/checkpoints/<任务id>/`，覆盖已有文件时算行级 diff；**move 覆盖已存在的目标时，目标原件同样在改前备份**（2026-10-25 起——此前只备来源，被覆盖的目标既不进检查点也无从恢复；回滚先归位再还原，顺序上有注释自证）；`backed` 的语义严格是"任务开始前就存在且已备原件"——中途新建的文件二次修改**不再**被当作有原件备份（此前会把中间态版本备进去，回滚后留下任务前不存在的文件，已修）。工作流整个任务共用 `run.id`（返工/续跑都回到任务开始前），工作站对话按 `reqId` 各一个。交付卡片与对话里能展开"本次改动 N 个文件 · 逐个看 diff · 回滚这些改动"；完全访问模式下的目录外改动也登记进清单并标"不可还原"（此前该警示是死代码带不到界面，已修）
- 交付可验收：① 开工前拍目录基线，交付时列出"相比开始前新增/消失了哪些文件"（包含命令与 CLI 造成的改动，回滚清单管不到但看得见）；② 验收项可指向产物文件（规划/审核输出 `files`，界面拿真实目录核对，指到不存在的文件当场标红）；③ 目录里 ≥2 个文件时自动生成「产物索引.md」
- 工作流编排：`中断续跑`（重启后按已有卡片推断该从谁接着跑，绝不重放已产出过结论的角色；审核已完成的那种重新摆到确认门前让人决定）、`单角色重跑`（每张角色卡片一个"重跑"，只跑那一个角色、不动确认门、新增一张卡片而不改写历史）、`角色级 Skill 绑定`（绑到哪个角色就只进那个角色的提示词，停用的技能即便绑了也不注入）
- 工具 Hook：模型 Agent 每次工具调用前后执行你自己配的命令（`pre` 退出码非 0 = 否决并把原因回传模型；`post` 只观察与后处理，失败不撤销已落盘的改动但如实报告）。**MCP 工具调用同样过这道 Hook**（2026-10-25 起——此前只有内置工具走，pre 否决对 MCP 不生效）。参数只走环境变量（`AHUB_HOOK_TOOL/_ARGS/_RESULT/_FILE/_DIR`）不做字符串拼接；args 超 30000 字符改走临时文件、env 传 `AHUB_HOOK_ARGS_FILE` 路径（2026-10-25 起——撞 Windows 单环境变量约 32K 上限时 spawn 失败会被误判成 Hook 否决），工作目录固定为沙箱根，超时默认 15 秒
- 工具 Hook 能认出"这条命令我改过没有"：设置页每条规则旁边给出脱敏回显 + 12 位指纹，指纹是对**归一化后的命令原文**算的显示用散列（折叠多余空白、转小写之后逐字符算；所以大小写与空白的不同写法同指纹，改任意一个其它字符——包括被遮成 `***` 的凭据值——指纹就变）。它只给人肉眼核对用，**永不参与放行判定**，也不是加密原语；命令长度上限 4096 字符，超长**拒绝保存并把当前长度告诉你**，不在背后替你截断（截断等于悄悄改掉要执行的命令）
- **保存配置不再销毁你没填错的那几条**：`hooks:set` 与 `mcp:set` 原先在落盘前按校验规则过滤**整表**，一条不合格的记录（例如手搓进 `config.json` 的 >4096 字符 Hook）会在你改动任意 Hook/MCP 设置时**静默消失**。现在校验闸门抽成纯函数（`src/shared/hooks.partitionHookRules` / `src/shared/mcp-list.partitionMcpServers`），**被拒条目原样留在配置里**，并把拒绝原因逐条回传设置页点名显示（拨一个无关开关也要能看见那条提示）——与"重填不得销毁旧记录"的既有先例同口径。真机断言钉在 `approval-shot`；**条数上限（Hook 40 / MCP 20 / 单价不设）现在只挡界面「新增」那一关**，落盘不再按条数截断（手改进来的更多条目原样保住，界面到上限把添加按钮禁用并说明）
- MCP 客户端（tools-only）：只接 server 的 **tools**（不接 prompts/resources，不让外部 server 往上下文塞系统提示），第一版只支持 **stdio**。信任模型：全局 server 列表 + 各 Agent 勾选启用，首次连接弹窗把**实际执行的 `bin` + `args` 整行**和工具清单一起摊开（旧格式记录则显示原命令并明写"已停用"），「始终信任」后整组放行（可随时撤销）；信任标记在主进程 `approvals.json`，删掉 server 时信任一起清掉。一条模型请求一套连接，流结束/报错/取消都关掉 server 进程

### 演示模式边界 ⚠️

演示 Agent 的回复、工具事件、产物均为脚本化内容，**不是真实模型输出**，产物不写盘，界面全程带"演示"徽章，绝不包装成真实执行。

### 未实现 / 已知限制 ❌

- **工作流不能并行执行**：引擎只有一个执行循环，任务列表是"多个可回看的工作流 + 同时只跑一个"，正在跑的时候切换/新建/删除都会被拦住；真并行要把引擎改成多实例（请求路由、取消、Token 上限、产物目录按任务隔离）
- **任务列表保留进度，不保留附件**：切换任务或重启后，文本与图片附件都要重新添加（附件正文可能几十 KB×N，不进持久化）
- **图片输入依赖模型支持视觉**：只有 OpenAI 兼容的 `image_url` 一条通路；`visionOf()` 是内置对照表，新模型未登记时按"提示后放行"处理，不做能力探测。CLI 侧不传图，只传本机路径
- **用量统计的口径受服务端限制**：token 与费用只在服务端返回 `usage` 时才有值；CLI 侧多数不上报，表里会标"未上报"而不是估算一个数
- **调用账本只存最近 2000 条**：滚动淘汰，不是完整账单历史；要长期留档需定期导出
- **占比环的分母只是"账本可见调用"，不是全量账单**：账本有 2000 条上限，且 CLI 多数不上报 usage。未上报的那些按**调用次数**单列一格「未上报」，绝不折算成 token（折了就是编一个数给你看）。所以环上那块"总计"回答的是"账本里看得见的这些调用怎么分布"，不回答"我一共花了多少"
- **计划态对 CLI 角色不构成任何写入约束**（v0.5.0，批次 F 的硬边界）：CLI 的写盘与命令由它自己的子进程执行，AgentHub 在这条链上只能下发提示词。因此计划轮结束后只做一件事——把**产物目录的路径清单差集**如实列出来（新增了什么、少了什么）。看不见 ≠ 没发生：原地改内容、只改大小写的重命名、先写后删，路径差集都看不出来；CLI 在它自己的工作目录里做了什么，这里更是看不到。界面上绝不出现"一定没改文件"这种话
- **计划态改为连你配置的 Hook 都不执行，代价是这一轮 Hook 的否决与审计也不生效**：Hook 是"每次工具调用时代你执行"的自定义 shell 命令，它自己能写盘，留在计划态里就会打破"批准前不产生改动"这句。取舍是刻意做的（保承诺优先于保审计）——想让 Hook 替你把关，就别用计划态跑这一次
- **计划态的门不叫后台通知（本版修了判定，通知本身仍需人眼确认）**：`announce()` 原先写的是 `waiting_review && gate`，而门挂出时状态其实是 `waiting_user`，等于所有确认门都不发通知；现在改成"有门且停在等人决定"就发，计划门单独措辞。系统级弹窗脚本量不到，属人工核验项
- **回滚只覆盖工具层的文件操作**：`write_file` / `replace_in_file` / `delete_file` / `move`（**含 move 覆盖已存在目标的那一份**，2026-10-25 起）与 AgentHub 自己的文本落盘在检查点清单里、可一键回滚；`run_command` 与 CLI Agent 自己写的文件不在这条链上，回滚撤销不了它们（目录对照能看到变化，但改不回来）。完全访问模式下的目录外改动不可还原但**会出现在清单里**（created 的目录外新建文件例外——回滚会删它，正是"回到任务开始前"）
- **CLI 角色写的文件能不能登记成产物，取决于它有没有把写盘事件报上来**：CodeBuddy 的 `Write`/`Edit` 与 codex 的 `file_change` 会被登记成角色卡片上的产物（标 `[tool]`）；没吐这类事件的那次写盘，AgentHub 无从知道，只能由交付时的目录对照兜住——产物索引按目录实况逐个列，来源记不出来的标「目录里存在（来源未记入工具清单）」，验收项映射照样能命中它。所以"卡片上没有产物"不等于"CLI 什么都没写"。真机层 `cli-workflow` 钉这件事：让 CLI 真写一个 `cli-note.md`，再交付前自己往目录里放一个"卡片没登记过"的文件，判**盘上每个真实存在的文件都被交代过**（登记或索引，二者必居其一）
- **命令审批只覆盖模型 Agent 的工具层**：CLI Agent 的命令确认由它自己的 CLI 负责（CodeBuddy/Codex 各自的权限模式），AgentHub 不替它做决定也不重复问；因此 CLI 路径上没有"逐条确认"这层
- **预算硬闸是下界**：只统计算得出金额的调用（有公开单价或自填单价），CLI 侧多数不上报 usage 也没有公开单价，那条链上预算闸基本不会触发。要真正兜住成本请同时设 Token 上限
- **repo map 是正则猜的，不是 AST/LSP**：只认行首声明，会漏（缩进的导出、宏生成的符号）也会错；注入时明确标注"当地图用，别当事实用"。刻意不引 LSP——多一套语言服务进程与安装成本，收益不匹配
- **摘要压缩是规则式的**：折叠最旧轮次时取每条开头拼成摘要，不调用模型做语义总结（省一次额度，但会丢细节）。摘要文本里写着"不是模型读完写的总结"，历史窗口截断也不冒充完整上下文
- **MCP 只支持 stdio 且只有 tools**：远程 HTTP/SSE server、prompts/resources、采样/roots 能力都没做。连不上时如实报一条提示并让其余工具照常工作
- **MCP 的 `.cmd` 家族仍经 cmd 启动**：Windows 上 `npx`/`npm`/`pnpm`/`yarn` 的真身是 `.CMD`（PATH 上没有同名 `.exe`），Node 对 `.bat/.cmd` 在非 shell 启动下另有专门限制，硬走 argv 只会 `ENOENT`。因此**不能声称"纯 shell:false"**——只有 argv 直传的 `.exe`/带路径脚本才是；界面与信任弹窗会在该 server 上标"经 cmd 启动"
- **经 cmd 那条路对参数有拒收规则（限制，不是防护完成）**：token 含 `"` `%` `&` `|` `^` `<` `>` **或换行（CR/LF）** 时直接拒绝启动并点名该参数（换行是 2026-10-25 补的——cmd 把 LF 当命令分隔符，与 `&` 同族）。依据是实测结论：cmd 的引号规则里没有"转义引号"这东西（`\"` 只是普通反斜杠 + 引号区在下一个 `"` 处关掉），`%` 在引号内照样展开，而 `cmd /d /c` 会剥掉首尾引号对——**加引号并不能让元字符变安全**，所以拒收与有没有空格无关。代价：`--filter="a b"`、`--out=x>y` 这类写法在这条分支上起不来（argv 直传那条不受影响）；同一行里出现第二对引号时 cmd 剥首尾引号会让该 server 起不来（旧实现同样起不来，不是能力回退，且失败是响的、不会退化成注入）
- **旧版 MCP 配置不自动迁移**：v0.3.x 填的单命令串在 v0.4.0 一律停用，需重填。刻意不猜拆分：拆错的命令行比"连不上"更难定位
- **Hook 不逐条问你**：配了 Hook 就等于让 AgentHub 在每次工具调用时代你执行那些命令，这是与命令审批不同的信任层，设置页红字标注
- **AgentHub 兜底落盘只保存执行结论正文**：执行角色没有文件能力时，成果由 AgentHub 写成一篇 `.md`（界面与文件开头都明写"由 AgentHub 落盘"）。这是文本交付，不是执行方自己写的代码文件，两者来源不混；同名产物文件已存在时自动追加 `-2`/`-3` 后缀（2026-10-25 起——同轮单角色重跑不再覆盖上一张卡登记的产物）
- **claude CLI 适配器未实测**：适配层已按官方 CLI 规范实现（见 docs/AGENT_ADAPTERS.md），但本机未安装，无法端到端验证；arkcli / codex / codebuddy / dsh 四个适配器均已本机实测
- **CodeBuddy CLI 需先登录**：装官方 CLI（`npm i -g @tencent-ai/codebuddy-code`）后在终端执行 `codebuddy` → `/login`（或设 `CODEBUDDY_API_KEY`）。WorkBuddy 内置的 lite 版**没有交互模式**，无法在其中登录，但它与官方 CLI 共享 `~/.codebuddy` 凭据，登录后同样可用
- **DSH headless 需模型凭据**：`dsh headless` 走 DeepSeek Harness 的凭据服务，启动环境里需要有 `DEEPSEEK_API_KEY`（或在 DSH 的 web profile Models 页写入），否则返回 `MISSING_CREDENTIAL`；且它的输出是纯文本非流式，卡片内容在任务结束时一次性出现
- **electron-builder 在本机打包需要管理员权限；"是安全软件拦的"这个旧结论已被实测推翻**：现象是确定的——`app-builder.exe` 的建目录/写文件在三个位置全报 `Access is denied`（`%LOCALAPPDATA%\electron\Cache\*.zip.partN`、`mkdir %LOCALAPPDATA%\electron-builder`、`mkdir D:\tmp\eb-cache\winCodeSign`），同样这些目录用 shell 能建出来，最终统一表现为 `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`；`-c.electronDist=node_modules/electron/dist` 与换 `ELECTRON_BUILDER_CACHE` 都救不了。但 2026-10-24 查下来，**归因不该写"本机安全软件按进程拦"**：这台机器只有 Microsoft Defender 在跑，而 `受控文件夹访问=关`、`ASR 规则=空`、`篡改防护=关`、`BlockAtFirstSeen` 未开——四个会把写文件变成 `Access denied` 的开关全是关的；Defender 的操作日志窗口覆盖 `10/18 10:19 → 10/24 22:09`（完整含做那三次实验的当天），里面**0 条提到 app-builder**，而它是会落这类事件的（`10/21 00:28` 就有一条 `Trojan:Win32/SuspExec.SE` 的命令行检测，来自另一个工具）。更吻合的解释是**权限**：本机实测当前会话不是管理员、开发者模式也没开（`AppModelUnlock\AllowDevelopmentWithoutDevLicense` 为空），因此令牌里没有创建符号链接的权限，而 electron-builder 解 `winCodeSign` 正需要它；"mkdir 用 shell 能建、app-builder 建不了"同一解释也覆盖——建目录不要那个权限，**建符号链接才要**。判定实验已经做了，**结论定了**：用提升后的进程跑 `npm run dist -- --publish never`（2026-10-24 23:32 起，约 7 分钟，`EXITCODE=0`；此时开发者模式仍关着，`devmode 0`），electron 缓存写入、`winCodeSign` 下载、NSIS 构建全部通过——所以卡点是**管理员身份**（非管理员时缺的就是创建符号链接那条权限），与安全软件无关。
- **NSIS 安装包与 asar 那层已经跑通了，本机和 runner 两边都通**：Release 工作流多了一条 `installer` 任务，手动触发（`workflow_dispatch`），产出 `AgentHub-Setup-0.5.0.exe` = **89.8 MB / sha256 `edbddfc1fbf9fc8b2c2f76131ca3557dac0288a75db3b519923a86e52aa53b70`**，并验了 `asar: true` 真生效：`release/win-unpacked/resources/app.asar` 存在、**旁边没有明文 `app/` 目录**、`@electron/asar` 列出 58 个条目且 `package.json` / `out/main/index.js` / `dist/renderer/bundle.js` 三条关键文件都在，安装包与 asar 清单作为 workflow artifact 保留 30 天。**本机用管理员权限跑同一条命令也出了同一个包**（`npm run dist -- --publish never`，`EXITCODE=0`）：`AgentHub-Setup-0.5.0.exe` = 94,117,135 字节（89.75 MiB，和 runner 报的 89.8 MB 是同一量级——我先前以为两边差了 3MB，是我把 MB/MiB 算错了）、sha256 `a9f0b94264f8e91e129519ee4b09397d7ff5839f8918c76e85ffd171364cfd06`；`app.asar` = 1,180,317 字节、同样 58 个条目、同样没有明文 `app/` 目录，`package.json`/`out/main/index.js`/`dist/renderer/bundle.js`/`dist/renderer/index.html`/`build/icon.ico` 全在。**两边产物可比对**，这条链路不再是单点。**第一次触发失败的原因不是构建**：electron-builder 一认出 CI 就去抢着发 GitHub Release（日志第二行 `artifacts will be published if draft release exists reason=CI detected`），而这条任务权限只有 `contents: read`、没有 token，于是**安装包已经建好之后**报 `GitHub Personal Access Token is not set` 把整条 job 拖红——加 `--publish never` 断开就行。**"装起来跑一次"这条也补上了**（2026-10-25 凌晨本机实测）：拿 `--dir` 产物 `win-unpacked\AgentHub.exe` 用**隔离的 user-data-dir** 起，CDP 取证 7/7 全过——渲染进程的文档 URL 是 `…\resources\app.asar\dist\renderer\index.html`（**真的从 asar 里加载**）、preload 桥在、store 水合、splash 渲染、按 Esc 进品牌首页（logo / "今天要构建什么" / composer / 附件钮 / 发送 / 工作站·工作流两颗 pill 都在，截图人眼核对过）。顺带量出两个环境边界，都**不是 asar 的问题**：① 这台机器必须带兼容开关（`--no-sandbox` 或 `AGENTHUB_NO_SANDBOX=1`）才起得来，不带就 45s 内 devtools 都不就绪——这正是便携包里 `start-compat-mode.cmd` 存在的理由；② 把 `--user-data-dir` 指到 `C:\…\Temp` 时这个包报 `process_singleton_win.cc:454 Lock file can not be created! - **便携版验证走 `pack:portable`**（纯 JS、**不打 asar**、明文 `resources/app`，便于你自己检查与修改）；要 asar 形态就用上一条那条任务出的安装包，或者本机**用管理员终端**跑 `npm run dist -- --publish never`（2026-10-24 实测通）。**不需要给 `app-builder.exe` 加安全软件白名单**：本机日志里没有 Defender 拦它的证据，而把身份提上去就全通了——降防护这一步可以整个省掉
- **Chromium 沙箱兼容模式**：部分装有大数字类安全软件的机器上，Electron 的 GPU/渲染沙箱子进程会被拦截崩溃（0xC0000005）。降级策略三态可选（设置 → 关于），`AGENTHUB_NO_SANDBOX=1` 与同目录 `start-compat-mode.cmd` 仍可用（降低渲染进程隔离；本应用只加载本地页面，无远程内容）。正常机器无需开启。徽章按**事实**出，所以用户自己设 `AGENTHUB_NO_SANDBOX=1` 启动时也会显示（刻意如此：它写的是"这台机器现在关了什么"）；选 `不自动降级` 时渲染进程连续崩溃会**直接启动失败**（这是选择，不是故障），需要手动跑 `start-compat-mode.cmd`
- **兼容徽章在开屏与品牌首页两屏看不见**：这两屏挂在 `Shell` 之外，所以"常驻"目前只在两种工作模式内成立（v0.5.0 顶栏批次收口；本轮刻意没把徽章搬进那两屏）。原先同一条目里的另外两件事**已修**：有待更新横幅时徽章会被盖住、以及徽章接走中间区域的点击
- **`file://` 判定的无锚弱回退仍偏宽**：调用方没传真实安装根时，判定退回 `resources/app/dist/renderer/` 标记匹配，于是 `file:////evil.example\share\resources\app\dist\renderer\…`（内容来自攻击者指定的远程共享）仍会放行。生产三个调用点都带真实根，所以今天只是测试面；收掉它需要无根时一律 `return false` 并给约 10 条无锚断言显式传根。**本轮补的是"调用点必须传锚"这件事**（控制器裁决 Ruling S，选更便宜的守法而不是收紧回退）：`fixes-check` 扫 `src/**` 每一处 `navDecision(` 调用、断言实参个数恒为 3，并钉一条"扫描器自己有牙"（`index.ts` 必须命中 3 处）防止空扫永真；锚非字符串时改为 **fail-closed 返回 block**，不再从导航回调里抛 `TypeError`。所以现在的保证是"生产路径不可能不带锚"，而不是"无锚判定变严了"——后者仍留给 v0.5.0
- **渲染层调试钩子在发布版里仍可调用（`tools:exec` 通道已收口，钩子层未动，v0.5.0 候选）**：`window.__ahub_debug` 在 `App.tsx` 的挂载 effect 里**无条件安装**（共 41 个键，不止 README 早先点名的 6 个），所以发布版也能调用 `startDemoTask` / `startCliTask` / `restoreWorkflowConfig` / `startMockToolTask` / `configRoundTrip` / `setUpdateBanner` / `decideApproval` / `execTool` / `rollbackCheckpoint` 这些钩子——它们里有的能起真 CLI 任务、有的能改配置、有的能代替人做审批。**这不是一个可以靠"发布版藏掉它"解决的问题**：一个能把脚本注入渲染层的攻击者，拿到的是整个 `window.agenthub` IPC 桥，`__ahub_debug` 只是它外面的一层包装，闸掉包装不等于闸掉桥，收益是假的。2026-10-25 已把 `tools:exec` IPC 通道本身收进 `--ahub-verify` 验证态闸门（与 `config:importJson` 同一道门）——渲染层自构造 grant（`access:'full'` 全盘读写）的自我提权通道关闭，验证套件带开关启动不受影响；`__ahub_debug` 钩子层与 IPC 桥的全面验证态化仍未做，列进候选
- **装在 UNC 路径上的应用无法在窗口内重载自己的页面**：`file://` 判定要求空主机（带主机名在 Windows 上就是 `\\server\share`，绝不能算本机页面），代价是网络盘安装形态下 F5/重载会被拦。启动走 `loadFile` 不触发 `will-navigate`，故开机不受影响
- **开发模式同源判定是字符串相等**：`VITE_DEV_SERVER_URL=http://localhost:5173` 时访问 `http://127.0.0.1:5173/` 会被判成外链转系统浏览器（`localhost` 与 `127.0.0.1` 视为不同源）；未打包形态下 `did-fail-load` 错误页的重试按钮会因重试 URL 被判 block 而失灵
- **ESLint 的保证面只有那 5 条 error 规则**：`innerHTML` 直接赋值 / `window.open` / `javascript:` URL / 动态 `href` 这些同样危险的写法**不在规则覆盖内**（今天 0 命中，靠人工维持，没有机器拦）；`react/no-danger` 也看不见经 prop 展开传进去的 HTML。计划与 spec 早期把这件事写成"注入面从此由机器保证"，那句已被最终评审判为夸大并订正。（同一条目原先还列着三件事——`noInlineConfig` 未设、`no-implied-eval` 全局名单两头不准、`verify/**` 与 `scripts/**` 零规则空转——三条都已在合并前修掉，见上方 ✅。）还有一条**规则之外的残留**：`scripts/build-renderer.mjs` 的 `shell:true` 带参数（DEP0190，Windows 上是既有噪声）不在那 5 条注入规则里，本轮没有为它加规则（加了就不再是 0 error），只做记录
- **需人工核验的三项**：`Ctrl+W`/Alt+F4 与托盘行为自 v0.3.0 起就标着"需人工核验"，本批没碰这段代码（风险没变大）但仍没人双击看过一次；真实图片输入后模型到底看到什么未复核；`npm run dev` 开发模式与 NSIS 安装包（`npm run dist`）本轮只过了类型检查/构建与逻辑断言，没人拿眼睛看过一次（真机层跑的是便携版部署形态）。**2026-10-25 审查修复轮（2 P0 / 12 P1 / 20 P2 / 21 P3，含工作流引擎并发、检查点语义、审批拆段器、适配器超时与行缓冲、Modal 焦点等界面修复）只过了逻辑层（fixes 602 断言）+ typecheck + lint，`verify:gui` 与 CLI 层未重跑**——发版前按惯例人工跑一轮真机层
- 自动更新：仅"检查 + 提示"（发现新版本显示横幅，用户前往 Releases 手动下载），不自动下载或安装
- **联网工具的 SSRF 残留面**：跳转目标在响应返回后按最终地址复核并丢弃内网响应体，但跳转到内网的那次请求本身已发出（盲 SSRF）；DNS 解析与真实请求之间的重新解析窗口（DNS rebinding）无法在本层消除
- **search_files 的静默边界**：遍历跳过 node_modules/.git/dist/out/release 等目录且文件数上限 5000，返回文案未向模型披露，可能把"存在但被跳过"报成"未找到"；模型可控正则的**灾难性回溯启发式**（嵌套量词、带量词的交替组、字符类连缀量词、量词连排）直接拒绝——启发式非完备（嵌套分组包住交替等形态会漏），线性时间引擎（RE2 类）才是根治，模式 200 长度上限兜底
- **流式用量依赖服务端**：未发送 `stream_options.include_usage`，部分 OpenAI 兼容服务端在流式下不返回 usage，此时不显示本轮 token/费用
- 平台：仅 Windows 已验证；macOS/Linux 未测试（架构上未使用 Windows 独有 API，除凭据存储走系统能力外）
